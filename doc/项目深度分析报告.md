# 项目深度分析报告：男妃AI超级智能体应用平台

---

## 一、项目概览

**「男妃AI超级智能体应用平台」** 是一个基于 **Spring AI Alibaba + Spring Boot 3.5 + Vue 3** 的全栈 AI Agent 应用平台。项目以 **ReAct（思考-行动）** 模式为核心，构建了一套支持工具调用、RAG 检索增强、SSE 流式响应的智能体（Agent）体系，并落地了两个面向用户的具体 AI 应用——**AI恋爱大师**（情感咨询）和 **AI超级智能体**（通用任务执行）。

项目还通过 **MCP（Model Context Protocol）协议** 集成了一个独立的图片搜索服务，实现了 Agent 生态的可扩展性。

### 选型关键考量

1. **Spring AI vs LangChain4j**：选择 Spring AI 生态是因为它与 Spring Boot 无缝集成，利用 Spring 的 DI、AOP、自动配置等能力，开发者无需额外学习 Agent 框架即可快速上手。而 Alibaba 的扩展版本对国内模型（通义千问）和云服务（阿里云知识库）支持良好。

2. **自研 Agent 框架 vs 开箱即用**：项目没有完全依赖 Spring AI 内置的 Agent 机制，而是基于 `BaseAgent → ReAcAgent → ToolCallAgent` 的自研层次结构。这样做的好处是全面掌控 Agent 的生命周期、状态流转、SSE 事件推送格式，前端可以实时展示思考过程、工具调用轨迹等结构化信息。

3. **文件持久化 vs 数据库**：对话记忆选择 Kryo 文件序列化而非数据库，显然是出于轻量化和开发便捷性的考虑。生产环境可轻松替换为 Redis 或 PostgreSQL 存储。

## 四、核心功能流程

### 4.1 AI恋爱大师（LoveApp）

**核心能力**：基于专业 System Prompt + 多轮对话记忆 + RAG 知识库检索 + 工具调用 + MCP 扩展

**请求处理流程**：

```
用户消息 → AiController (/ai/love_app/chat/sse)
         │
         ▼
LoveApp.doChatStream(message, chatId)
         │
         ├─ ChatClient 调用 LLM (qwen-plus)
         │    ├─ DefaultSystem: 恋爱专家 System Prompt
         │    ├─ Advisors:
         │    │   ├─ MessageChatMemoryAdvisor (对话记忆)
         │    │   └─ MyLoggerAdvisor (日志)
         │    └─ stream().content()  →  Flux<String>
         │
         └─ 返回 Flux → Controller 转换为 SSE 流式输出
```

**RAG 增强路径**（独立方法 `doChatWithRag`）：

```
用户消息 → QueryRewriter.doQueryRewrite()  [查询重写]
         │
         ▼
重写后查询 → QuestionAnswerAdvisor(loveAppVectorStore)
         │              ├─ 向量检索相似文档
         │              └─ 将上下文注入 Prompt
         ▼
LLM 生成回答
```

**文档处理流水线**（初始化时）：

```
resource/document/*.md
         │
         ▼
LoveAppDocumentLoader.loadMarkdowns()
         │  [MarkdownDocumentReader 读取 + 元信息提取]
         ▼
MyKeywordEnricher.enrichDocuments()
         │  [KeywordMetadataEnricher: AI提取关键词]
         ▼
SimpleVectorStore.add(enrichedDocuments)
         │  [DashScope Embedding Model 向量化 + 存储]
         ▼
向量数据库就绪 → QuestionAnswerAdvisor 查询使用
```

### 4.2 AI超级智能体 (YuManus → ToolCallAgent)

**核心能力**：基于 ReAct（思考-行动）循环的自主任务执行，支持最多 20 步的工具调用

**请求处理流程**：

```
用户消息 → AiController (/ai/manus/chat)  →  SSE
         │
         ▼
YuManus.runStream(prompt)
         │
         ▼
BaseAgent.runStream()
         ├─ 创建 SseEmitter(5min超时)
         ├─ CompletableFuture 异步执行
         │
         ├─ [循环] for i=0..maxSteps:
         │      │
         │      ▼
         │   ReAcAgent.step()   ← 单步：先 think 再 act
         │      │
         │      ├─ ToolCallAgent.think()
         │      │   ├─ 拼接 SystemPrompt + 历史消息 + NextStepPrompt
         │      │   ├─ 调用 ChatClient + toolCallbacks(7个工具)
         │      │   ├─ 解析 LLM 响应
         │      │   │   ├─ 有工具调用 → emitThink() + emitToolCall() → return true
         │      │   │   └─ 无工具调用 → emitAnswer() → setState(FINISHED)
         │      │   └─ 异常 → emitError()
         │      │
         │      └─ if shouldAct:
         │            ToolCallAgent.act()
         │              ├─ toolCallingManager.executeToolCalls() 执行工具
         │              ├─ emitToolResult() 推送结果
         │              ├─ 检查是否调用了 doTerminate
         │              └─ 更新消息列表 (conversationHistory)
         │
         └─ 循环结束 / 达到 maxSteps → emitDone() → 发送 [DONE]
```

### 4.3 前端 SSE 事件流处理

```
SuperAgent.vue (sendMessage)

EventSource → /api/ai/manus/chat?message=xxx
         │
         ├─ [事件] onmessage
         │      ├─ 收到 "[DONE]" → 关闭连接
         │      └─ 收到 JSON → AgentStreamEvent
         │            ├─ type: "agent_start" / "step_start" / "think"
         │            │         / "tool_call" / "tool_result" / "answer"
         │            │         / "error" / "done"
         │            ├─ content: 思考内容/回答/错误
         │            ├─ toolName + arguments: 工具调用
         │            ├─ toolResult: 工具结果
         │            ├─ step + maxSteps: 步骤信息
         │            └─ reason: 结束原因
         │
         └─ applyAgentEvent(trace, evt)
               └─ 响应式更新 trace 对象 → AgentTraceCard 实时渲染
```

```
主应用 (ai-agent-lasted)                MCP Server (nanfei-image-search-mcp)
```

## 五、关键设计模式

### 5.1 模板方法模式（Template Method）

**应用位置**：`BaseAgent` → `ReAcAgent` → `ToolCallAgent`

`BaseAgent` 定义了 Agent 执行的骨架算法（`run()` / `runStream()` 中的多步循环），子类 `ReAcAgent` 将"单步"抽象为 `think()` + `act()`，而 `ToolCallAgent` 具体实现如何与 LLM 交互、如何执行工具调用。

```
BaseAgent.run()
    ├─ 状态检查 (IDLE)
    ├─ 循环 maxSteps 次:
    │     └─ step() [抽象方法 → 子类实现]
    ├─ 状态更新
    └─ cleanup()

ReAcAgent.step()  [模板方法]
    ├─ think() [抽象，子类实现]
    └─ if shouldAct → act() [抽象，子类实现]
```

### 5.2 责任链模式（Chain of Responsibility）

**应用位置**：Spring AI 的 Advisor 机制

Spring AI 的 `Advisor` 本质是责任链模式——多个 Advisor 组成链，依次在 LLM 请求前后执行拦截逻辑：

```
ChatClient.prompt().user("...")
    .advisors(
        MessageChatMemoryAdvisor    → 注入对话历史
        ReReadingAdvisor            → 重读用户输入
        MyLoggerAdvisor             → 记录请求/响应日志
        QuestionAnswerAdvisor       → 注入 RAG 检索结果
    )
    .call()
```

每个 Advisor 的 `before()` 修改请求（注入上下文），`after()` 处理响应。

### 5.3 策略模式（Strategy）

**应用位置**：RAG 的多种检索策略

`LoveApp` 提供了多种 RAG 检索策略，可灵活切换：

| 策略 | 实现 | 适用场景 |
|------|------|---------|
| **本地向量检索** | `QuestionAnswerAdvisor + SimpleVectorStore` | 本地 Markdown 文档矢量查询 |
| **云端知识库检索** | `DashScopeDocumentRetriever + RetrievalAugmentationAdvisor` | 阿里云知识库服务 |
| **自定义过滤检索** | `VectorStoreDocumentRetriever + status过滤` | 按状态（单身/恋爱/已婚）过滤文档 |
| **纯对话模式** | 无 Advisors | 快速对话，不依赖知识库 |

### 5.4 建造者模式（Builder Pattern）

**应用位置**：`ChatClient` 构建、`AgentStreamEvent` 构建

Spring AI 的 `ChatClient` 使用 Builder 模式（`ChatClient.builder(model).defaultSystem(...).defaultAdvisors(...).build()`），Agent流式事件也使用 Lombok `@Builder` 注解生成 Builder：

```java
emitEvent(AgentStreamEvent.builder()
        .type(AgentEventType.THINK)
        .content(content)
        .build());
```

### 5.5 观察者模式 + SSE（Server-Sent Events）

**应用位置**：`SseEmitter` 的流式推送

Agent 的执行过程通过 SSE 实时推送到前端。`BaseAgent` 维护一个 `SseEmitter` 实例，子类在 `think()` 和 `act()` 中通过 `emitXxx()` 方法推送结构化事件。前端通过 `EventSource` 订阅并实时更新 UI。

```
[后端 Agent]                  [前端]
    │                           │
    ├─ emitThink("...") ──SSE──→ 展开思考过程
    ├─ emitToolCall(...) ──SSE──→ 显示工具调用
    ├─ emitToolResult(...)─SSE──→ 显示工具结果
    ├─ emitAnswer(...) ──SSE───→ 显示最终回答
    └─ emitDone(...) ──SSE────→ 标记完成
```

事件类型枚举（`AgentEventType`）设计了 8 种事件：`agent_start`, `step_start`, `think`, `tool_call`, `tool_result`, `answer`, `error`, `done`。

### 5.6 工厂模式（Factory Pattern）

**应用位置**：`ToolRegistration`、`LoveAppRagCustomAdvisorFactory`

- **工具工厂**：`ToolRegistration` 作为 `@Configuration` 工厂类，统一创建并注册所有 `ToolCallback`
- **RAG 工厂**：`LoveAppRagCustomAdvisorFactory` 负责根据参数动态创建自定义 RAG Advisor

### 5.7 适配器模式（Adapter Pattern）

**应用位置**：Spring AI 的 `@Tool` 注解适配

项目中的 7 个工具类（`WebSearchTool`, `FileOperationTool` 等）通过 Spring AI 的 `@Tool` 注解标注，`ToolCallbacks.from()` 方法将这些 POJO 适配为 LLM 可调用的 `ToolCallback` 接口，实现业务代码与 Agent 框架的解耦。

### 5.8 序列化策略模式（Serialization Strategy）

**应用位置**：`FileBasedChatMemory`

对话记忆使用 Kryo 高性能序列化存储到文件，支持滑动窗口（`maxMessages` 参数），超过上限自动截断最旧消息。这比 Java 原生序列化性能高 10-100 倍。

## 六、MCP（Model Context Protocol）集成分析

项目通过 Spring AI 的 MCP 客户端和服务器模块，实现了一个独立的图片搜索服务：

**MCP Server** (`nanfei-image-search-mcp`)：
- 独立 Spring Boot 项目，通过 `spring-ai-starter-mcp-server-webmvc` 启动
- 提供 `ImageSearchTool`，调用 Pexels API 搜索图片
- 通过 stdio 协议与主应用通信

**MCP Client**（主应用）：
- `mcp-servers.json` 配置 MCP Server 的启动命令
- `SyncMcpToolCallbackProvider` 加载并注册 MCP 工具
- `LoveApp.doChatWithMcp()` 方法演示如何在聊天中集成 MCP 工具

**为什么使用 MCP**：
- 解耦：图片搜索能力作为独立服务运行，不影响主应用稳定性
- 标准化：MCP 是 AI 模型的标准化工具协议，一次实现可在多个 Agent 中复用
- 生态扩展：未来可以添加更多 MCP Server（天气、地图、支付等）

## 七、数据流与状态管理

### 7.1 Agent 状态机

```
                    run()/runStream()
    ┌─────┐   ──────────────▶   ┌─────────┐
    │ IDLE │                     │ RUNNING │
    └─────┘                     └────┬────┘
              ◀─────────────────      │
              cleanup()               │ step() 循环
                                      │
                          ┌───────────┴───────────┐
                          ▼                       ▼
                    ┌─────────┐             ┌─────────┐
                    │FINISHED │             │  ERROR  │
                    └─────────┘             └─────────┘
```

### 7.2 消息上下文管理

```
ToolCallAgent 的上下文维护流程：

1. think():
   - 添加 NextStepPrompt → messageList
   - ChatClient.prompt(messageList).call()
   - 结果中无工具：assistantMessage → messageList
   - 结果中有工具：记录 toolCallChatResponse

2. act():
   - toolCallingManager.executeToolCalls(prompt, toolCallChatResponse)
   - 返回 conversationHistory → setMessageList()

3. 循环：
   - 下一轮 think() 时，messageList 已包含：
     [用户消息, 助手思考1, 工具结果1, 下一轮提示, ...]
```

### 7.3 对话记忆持久化

```
LoveApp 初始化时：
  ChatMemory = FileBasedChatMemory("tmp/chat-memory", maxMessages=10)

每次对话（通过 CONVERSATION_ID）：
  get(chatId) → 读取 .kryo 文件 → 反序列化 List<Message>
  add(chatId, messages) → 序列化 List<Message> → 写入 .kryo 文件
  超过10条 → 滑动窗口截断最旧的
```

## 八、项目亮点与改进建议

### 8.1 项目亮点

1. **自研 Agent 框架**：从零构建的层次化 Agent 架构（BaseAgent → ReAcAgent → ToolCallAgent），对 Agent 执行流程有完全控制力
2. **结构化 SSE 事件设计**：8种事件类型覆盖 Agent 执行全生命周期，前端 AgentTraceCard 组件直接映射这些事件，实现精细化的执行轨迹展示
3. **RAG 多策略支持**：本地向量检索、云端知识库、自定义过滤三种策略可任意组合
4. **MCP 生态扩展**：通过 MCP 协议集成外部服务，体现了良好的可扩展性
5. **赛博朋克UI**：前端采用赛博朋克风格设计，Glitch 故障效果、扫描线、极光背景等视觉元素，给用户强烈的科技感

### 8.2 潜在改进方向

1. **数据库持久化**：对话记忆目前使用文件存储，生产环境建议迁移到 Redis 或 PostgreSQL，提升并发可靠性和数据管理能力
2. **多模型支持**：目前硬编码 qwen-plus，可抽象为可配置的多模型路由（如紧急用 GPT-4、日常用 qwen）
3. **Agent 监控面板**：可增加 Agent 执行统计（平均步数、工具使用频率、响应时间等）
4. **用户认证**：目前无认证机制，生产环境需补充 JWT/OAuth2
5. **记忆持久化配置**：BaseAgent 的 messageList 是纯内存结构，重启后丢失，可对接 ChatMemory 实现持久化
6. **Agent 间通信**：目前两个 Agent 完全独立，未来可设计 Agent 编排能力，让多个 Agent 协作完成复杂任务

## 九、总结

「男妃AI超级智能体应用平台」是一个架构清晰、技术选型合理、实现完整的 AI Agent 应用平台。它通过 **Spring AI Alibaba** 生态与自研 Agent 框架的良好结合，实现了从 LLM 调用、工具执行、RAG 检索增强到前端实时流式展示的完整闭环。项目虽然是个人开发性质，但代码组织规范、设计模式运用得当，体现了对 AI Agent 架构的深刻理解。特别是 SSE 结构化事件推送机制和 MCP 协议集成，为后续功能扩展奠定了良好基础。
